## Source/design evidence groups

### NATIVE: Native evidence validation and independent sections

Reuse one authenticated native verification path; evidence availability, schema validation, graph interpretation, and local policy remain distinct. Preserve exact disclosed bytes and existing wire/profile decisions.

Decision detail: [provenance.md#r2r3-a-shared-native-semantic-context-and-restart-lookup](provenance.md#r2r3-a-shared-native-semantic-context-and-restart-lookup).

Bounded idea/adaptation sources: [profile.md#approved-provisional-interpretation](profile.md#approved-provisional-interpretation), [profile.md#graph-and-bound-state-decisions](profile.md#graph-and-bound-state-decisions), [donor-notices.md](donor-notices.md).

Pinned profile resolves specific ambiguous wire contracts; it is not universal conformance. Comparison donor frameworks are not presumed copied.

### CUSTODY: Optional per-registry private derivation and thin inventory

Keep grant-specific consent and issued bytes in ordinary storage; separate optional encrypted salt handling, require explicit opening verification, and retain exact history without a current-standing claim.

Decision detail: [provenance.md](provenance.md).

Bounded idea/adaptation sources: [profile.md#ownership-and-observable-states](profile.md#ownership-and-observable-states), [https://github.com/keri-foundation/locksmith/tree/3a5ad9ebcf98b4ec03baf1bbb91d928d49c168e4](https://github.com/keri-foundation/locksmith/tree/3a5ad9ebcf98b4ec03baf1bbb91d928d49c168e4).

Locksmith informs the small reference model; no runtime code dependency or per-symbol copying is inferred. Keeper rotation does not migrate custody; plaintext re-import is recovery.

### SERVICES: Registrar hosting and independent observer acquisition

Reuse ordinary KEL/TEL authentication and service routing, while making source acquisition independent of presentation/cache queries and scheduling maintenance with the concrete owner.

Decision detail: [provenance.md#r5-a-service-owned-kram-pruning](provenance.md#r5-a-service-owned-kram-pruning).

Bounded idea/adaptation sources: [donor-notices.md](donor-notices.md), [https://github.com/keri-foundation/kf-registrar/tree/bf14eac4d644275a13cbd3c5900cc2e4dd7c11d1](https://github.com/keri-foundation/kf-registrar/tree/bf14eac4d644275a13cbd3c5900cc2e4dd7c11d1), [https://github.com/keri-foundation/kf-observer/tree/d6368aef9497452f5aa2a0657abe1adf5645c69b](https://github.com/keri-foundation/kf-observer/tree/d6368aef9497452f5aa2a0657abe1adf5645c69b).

Module headers attest donor route/topology adaptation. Exact copied-snippet ancestry is not independently proven for every new method; this remains an explicitly bounded donor-attribution uncertainty, not an assertion of direct copying.

### GROUP: Explicit native group approval and shared evidence ownership

Compose existing GroupHab/Counselor/Multiplexor/StreamPoster owners. Receiving proposals does not supply local approval; share parser schema evidence and give each Kramer one pruning owner.

Decision detail: [provenance.md#r3-cr5-c-group-section-intake-and-runtime-ownership](provenance.md#r3-cr5-c-group-section-intake-and-runtime-ownership).

Bounded idea/adaptation sources: [profile.md#ownership-and-observable-states](profile.md#ownership-and-observable-states).

Local explicit consent and quorum behavior do not create a new multisig protocol or automatically delegate private custody.

### TRANSPORT: Existing transport/CLI boundary adaptations

Use the existing request/receipt/public-method contracts reached by native lifecycle flows, preserving exact protocol metadata, framing, and process failure status.

Decision detail: [provenance.md](provenance.md).

Bounded idea/adaptation sources: [profile.md#ownership-and-observable-states](profile.md#ownership-and-observable-states).

Only the actual changed functions/snippets in the inventory are covered; nearby untouched upstream implementation remains inherited.

### CLI: Native command selection and local capability composition

Select existing concrete protocol owners from explicit CLI intent, retain ordinary identity authentication, and make custody provisioning/derivation optional rather than an inventory prerequisite.

Decision detail: [provenance.md](provenance.md).

Bounded idea/adaptation sources: [profile.md](profile.md), [legacy-peers.md](https://github.com/kentbull/keripy/blob/81964a69e0dd9897c37654e80bb2d9cc7b6e2934/docs/v2-e2e/legacy-peers.md).

Working CLI changes remain WIP until their parent-owned validation and provenance pass are reconciled.

### INFRA: Core-only installed-package tooling

The retained Dockerfile, check runner and requirements lock exercise KERIpy alone.
Their local copied-source/named-volume rationale and source ancestry remain in
[provenance.md](provenance.md#core-only-installed-package-test-tooling).
Cross-repository orchestration and its complete historical ledger are owned by
the independent experiment repository.
